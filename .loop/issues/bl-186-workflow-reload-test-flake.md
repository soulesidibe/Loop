This issue also carries bl-243 (ClaudeCodeTrackerToolsTest m4-14). A race in the test fixture; the production code works as specified. `Orchestrator.followWorkflow` (around line 1475) records one `config_reload_failed` per distinct rejected hash, and `Preflight.run` reads the file once, so the hash and the error always describe the same text. But `LoopFixture.writeWorkflow` (`cli/src/test/kotlin/loop/cli/LoopFixture.kt:82`) uses `Path.writeText`, which truncates then writes; a poll in between reads an empty or partial `WORKFLOW.md`, a different invalid text, rejected as a second one, so `.single()` at line 152 throws. bl-243 is almost certainly fixed already by bl-215's commit 2d8c1ba (`TranscriptReplay.replaceAtomically`): the two parallel fake claudes copied the MCP config to one shared `record/mcp.json` with a delete then create copy, and under load the fake exited 1 before any line, bl-243's exact symptom; bl-243 was seen on bl-205's tree e5f2de8, before 2d8c1ba.
