## What

With `ci: actions` (m3-15), every Actions run of the merged head counts: runs are grouped by `workflow_id` and `event`, the highest `run_number` kept, and all must be green. A repository whose Actions include workflows that should not gate a merge (a nightly job, a stale bot, a deploy preview, a labeler) has no way to leave them out, so an unrelated red or long running workflow blocks or times out every merge.

Possible direction for triage: an optional `ci_workflows` list under `merge` naming the workflows (by file path or name) that gate; absent means every workflow, as today. Loop's own repository has one workflow, `build.yml`, so it needs none of this today.
