## What

m1-02 (with m1-20) made the command runner start each agent script in its own session, so the runner can signal the whole process group on exit and on cancel. Java's `ProcessBuilder` cannot call `setsid` or `setpgid` between fork and exec, so the runner spawns `perl -MPOSIX=setsid -e ... sh -c <command>`. Loop now requires perl on PATH.

That works on macOS and Ubuntu today, but it is a runtime requirement users will hit:

- minimal container images (Alpine, distroless, slim) often have no perl;
- Apple said in the Catalina release notes that future macOS versions will not ship scripting runtimes by default (Python 2 is already gone, perl still ships).

Other runtimes expose this directly at spawn (Node `detached: true`, Go `SysProcAttr.Setpgid`, Rust `CommandExt::process_group`). The JVM is the odd one out.

## Decision gate

A grill me session with the maintainer must settle the choice before any implementation. Record the outcome as an ADR in `docs/adr/` and in this issue's comments, then relabel the issue (`ready-for-agent` or `ready-for-human`) with acceptance criteria that match the chosen option.

## Options

| Option | Platforms | Cost and risks |
|---|---|---|
| A. Keep perl `setsid` (current) | macOS, most Linux | Zero work. Breaks in minimal containers, and at risk if macOS drops perl. |
| B. `setsid` binary first, perl as fallback | Linux (util-linux, busybox on Alpine) via `setsid`; macOS via perl | Small change. Narrows the perl requirement to macOS, where it still ships. Two launch paths to test. |
| C. Java FFM calling `posix_spawn` with `POSIX_SPAWN_SETSID` | macOS, Linux | No external dependency. Needs JDK 22 or later (Loop targets 21), and Loop must own the pipe and stream plumbing that `ProcessBuilder` gives for free. A lot of code to own. |
| D. JNA or JNI | macOS, Linux | A native dependency, which the project has avoided so far. |
| E. A tiny bundled launcher binary (C, Go or Rust) | macOS, Linux | Robust and common in serious tools (for example `tini`). Per platform builds to ship with the distribution. |
| F. cgroups (`systemd-run --scope`) or a container per attempt | Linux only | The only option that also contains processes that call `setsid` themselves. Overlaps with future agent sandboxing, where containment may come for free. |

Not viable: `set -m` in the shell (dash disables job control without a terminal), relying on Python (not guaranteed on macOS).

Whichever option wins, also decide whether Loop checks the launcher dependency at startup (a clear error before the first turn, or a `loop doctor` style check) rather than failing at the first spawn.

## Questions for the grill me session

- Where must Loop run in M1 to M3: dev machines only, CI runners, containers?
- Is a perl requirement on macOS acceptable for now?
- Does agent sandboxing (F) belong to a later milestone, and should this decision wait for it?
- Is moving the toolchain to JDK 22 or later on the table (C)?
- Are we willing to ship and sign native binaries (E)?
