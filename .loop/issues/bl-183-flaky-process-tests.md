## Parent

None. Backlog, not scheduled in a milestone. Seen on 2026-11-22 during the bl-178 delivery, where these failures cost two local reruns and one red CI that went to a human.

## What

Several `cli` tests start a real `loop` process (`LoopFixture.start`) and wait a fixed 60 seconds for it to reply, exit or move an issue. Under load they miss the deadline although the work completes, and the failure looks like a real defect.

Failures seen on 2026-11-22:

- `ToolMcpCommandTest`, "m3-14 a reply over tool_output_tokens is trimmed, and its full text is kept for the attempt file": `loop tool mcp did not exit in 60s`, after the reply had been written. Local merge check of bl-178, 11:10.
- `ToolMcpCommandTest`, "an unknown state or an empty comment over MCP is a tool error, and nothing is queued (m2-17)": `AssertionFailedError at ToolMcpCommandTest.kt:73` (the `submit` helper's 60 second reply wait). GitHub CI of bl-178, ubuntu runner, run 45037593826, 15:32. Not on the operator's Mac, so not only local load.
- `TraceCommandTest`, "prints phases in order with their ids": `loop run ... --once did not exit in 60s`. The command runner's attempt itself took 73 s, so the run finished after the deadline. Local, 11:13, load average above 40.
- `WaitingCommandTest`, "a check interrupted by kill -9 still waits after the restart and runs again at startup": "the rerun check never moved the issue" (`awaitState`, `WAIT_NANOS`). Local merge check of bl-178, 14:52.

`LoopFixture` writes a diagnostics file under `$TMPDIR/loop-hangs/` on a timeout, but the files of today hold the process list and an empty thread section, so the thread dump of the hung process is missing. Five such files were written on 2026-11-22.

To weigh: one shared deadline for process tests, longer than 60 s and set by a system property, so CI and a loaded machine can raise it; a working thread dump in the hang diagnostics; and for `ToolMcpCommandTest`, whether the process really hangs after its reply (stdin close, MCP SDK shutdown), since it failed on an unloaded CI runner too.

## Acceptance criteria

- [ ] Each test above either passes under a raised, shared deadline or has a real hang found and fixed (judgment).
- [ ] The hang diagnostics include the thread dump of the timed out process.
- [ ] `./gradlew --no-daemon build` passes.
