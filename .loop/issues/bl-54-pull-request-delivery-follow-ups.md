## Agent brief

**Category:** bug

**Summary:** With pull request delivery, refute what can never be pushed before running the checks, and class a push that can never succeed as a failed delivery instead of retrying it every tick.

**Current behavior:**
- When the kind delivers a pull request and the work tree holds uncommitted or untracked files, Loop knows it when it takes the fingerprint, runs every check and holdout anyway, and only then refutes. A long suite runs for nothing.
- A workspace whose `HEAD` is detached or on a branch other than `loop/<workspace key>`, and a workspace whose fingerprint is not a git one (`tree:` or unknown), can be verified. Delivery then fails with `delivery_failed` after every `loop approve`, since there is nothing to push.
- A push that git answers with "Repository not found" (what GitHub says to a token without access to the repository), or to a remote that does not exist, is classed as unavailable and tried again at every tick, with a warn log and no event.

**Desired behavior:**
- With `delivery.pull_request`, a verification whose work tree holds uncommitted or untracked files is refuted before the first check runs. The findings and the `verdict` event are the ones of today (`uncommitted` count, the files named), and `checks` is 0. No evidence file is written for checks that did not run. Without `delivery.pull_request` nothing changes.
- With `delivery.pull_request`, a verification is refuted before the first check when the workspace is not a git work tree with a commit, or when its `HEAD` is not the branch `loop/<workspace key>`. The findings tell the agent what is wrong and what to do (commit on `loop/<workspace key>`, never switch branches), in the style of the uncommitted findings. A fingerprint Loop could not take stays `unverified`, as today.
- A push whose answer shows the repository is not there or not visible to the token is `DeliveryError.Rejected`: `delivery_failed` is recorded once and the wait goes back to an unapproved `Waiting(approval)`, as for an authentication failure. Unreachable hosts, timeouts and 5xx stay unavailable and are retried.
- The merge check's own recheck (a verification on the merged head) keeps passing through the same rules without a false refutation.

**Key interfaces:**
- `Verification.verify()`, `uncommittedFiles`, `VerifyFindings.uncommitted`, `UncommittedFiles`, the `verdict` event data.
- `WorkspaceFingerprint` (`committedHead`, the `git:` and `tree:` forms), `WorkspaceGit` for reading the branch of `HEAD`.
- `PullRequestDelivery.branch(workspaceKey)`.
- `GitPush` push classing (`AUTH_FAILURE`, `DeliveryError.Rejected`, `DeliveryError.Unavailable`).

**Out of scope:**
- The second comment after a crash and failed store writes of the wait (bl-42).
- Any change to what counts as dirty or to the fingerprint (bl-20).
- A push retry budget or backoff.
