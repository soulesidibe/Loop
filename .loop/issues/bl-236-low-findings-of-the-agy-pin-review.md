## What

1. **`file://` paths outside `locations[].uri` are not normalized** (`AcpPermissionPolicy`, the location and `extractInputPaths` reading). Only `locations[].uri` has its `file://` prefix stripped. A `file:///...` value in `locations[].path` or in a `rawInput` or `args` path key is read as a workspace relative path (`<workspace>/file:/tmp/holdout/x`), so the holdout and protected roots checks do not match it. The guards hold today only because agy 1.5.18 sends the resolved plain absolute path in `locations[].path` (checked by the Fable recheck with real `read_file` and `write_file` calls by URI); `args.Path` and `rawInput.Path` keep the raw `file:///` string. A later agy, or a tool that sends only the URI, would get a holdout read allowed. Normalize `file://` and percent encoding on every extracted path, with a policy test built from a real 1.5.18 frame.
2. **Preflight reads the first version-like token** (`AgyPreflight.extractSemver`). A banner such as `new version 1.6.0 available` printed before the real version would let an older agy pass preflight. The `initialize` check still refuses it on every spawn, so this costs a clear startup message, not safety. Read the version from the line that is only a version, or the last token, and test a banner.
3. **An agy that becomes too old mid run fails each attempt as an ordinary failure** (`AcpHandshakeFailure.AgyTooOld` and `WrongAgyMajorVersion`, with no category). If agy is downgraded during a run, or preflight and the runner resolve different binaries (preflight uses `host.env`, the runner `host.rawEnv` plus the agent env), every attempt fails and spends retries instead of holding or stopping the run. Triage decides between `runner_unavailable` (hold) and a run stop.
4. **Two docs still say major only:** the KDoc of `runnerPreflight` in `cli/src/main/kotlin/loop/cli/Host.kt` ("pinned major version `1`") and the line of `.loop/specs/gemini-support.md` that says "version on pinned major `1`". Add the 1.5.18 minimum.
5. **Note, no change asked:** `command: agy acp` without `preset: agy` runs as generic ACP, with no version check and no strict settings. That is the existing generic ACP behavior; say so in `docs/plugins/runner-acp.md` if it is not clear there.

## Agent Brief

**Category:** bug
**Summary:** the acp permission policy normalizes `file://` URIs on every path it checks, preflight reads the agy version robustly, a too old agy holds the run, and two docs name the minimum.

**Current behavior:**
`AcpPermissionPolicy` strips `file://` only from `locations[].uri`. A `file:///...` value in `locations[].path` or in a `rawInput` or `args` path key is read as a workspace relative path, so the holdout and protected roots checks never match it. The guards hold today only because agy 1.5.18 also sends the resolved plain path in `locations[].path`. `AgyPreflight` takes the first version-like token of `agy --version`. A too old or wrong major agy found at a session's `initialize` is an ordinary `TurnFailed` with no category, so each attempt spends a retry slot.

**Desired behavior:**
1. **Paths:** every path the policy extracts, from `locations[].path`, `locations[].uri` and every `rawInput` or `args` path key, goes through one normalization before any check: a `file:` URI (`file:///x`, `file://localhost/x`) becomes its absolute path, percent encoding is decoded, and any other URI scheme fails closed (the request is declined with a `loop:` line naming the scheme, never read as a relative path). Plain paths are unchanged. The holdout, protected roots, `--gemini-dir` and attempt folder checks then see the real path.
2. **Version reading:** preflight takes the version from a line of `agy --version` that is only a version, else the last version-like token, and a banner such as `new version 1.6.0 available` before it never decides.
3. **Too old agy holds the run:** a `WrongAgyMajorVersion` or `AgyTooOld` failure at `initialize` under `preset: agy` is a `TurnFailed` with category `runner_unavailable`, so it takes no `max_attempts` slot and the run level hold probes until agy is updated. The reason text is unchanged. `UnknownAgyVersion` stays an ordinary failure.
4. **Docs:** the `runnerPreflight` KDoc and `.loop/specs/gemini-support.md` say pinned major `1` and at least 1.5.18. `docs/plugins/runner-acp.md` states the `file://` normalization and the hold, and that `command: agy acp` without `preset: agy` runs as generic ACP with no version check and no strict settings.

**Key interfaces:**
- `AcpPermissionPolicy` path extraction (`extractLocationPaths`, `extractInputPaths`).
- `AgyPreflight` version extraction.
- `AcpHandshakeFailure.AgyTooOld`, `WrongAgyMajorVersion` and how `AcpRunner` maps a handshake failure to `RunnerEvent.TurnFailed.category`.

**Out of scope:**
- Changing the pin or the minimum.
- Generic ACP without a preset.
- The hold rules themselves (`RunnerHold`).
