## What

- **Reload not applied.** `trusted_associations` is validated on a workflow reload but the tracker keeps the startup set (`OpenProject.kt:88-92`, `GitHubTracker.kt:54`). Narrowing trust on a running Loop needs a restart, silently. Pass a live supplier like `requiredLabels`, or say it in `docs/plugins/tracker-github.md`.
- **Rotation renders a no longer trusted issue.** `rotationIssue` (`Orchestrator.kt:2973-2988`) renders the fresh issue without checking `dispatchable`, so an author who lost trust mid run could get an edited body into one rotated prompt before the next tick stops the attempt. Fall back to `held` when `fresh.dispatchable` is false.
- **Docs caveats.** `tracker-github.md` around line 183: with a narrowed list (for example `[OWNER]`), a collaborator can still edit the owner's body, so "trusted author means trusted editors" holds only for the default list. Around line 184: a GitHub App or bot token usually has association `NONE`, so Loop's own comments would be hidden, and org members with private membership can read as `CONTRIBUTOR` or `NONE`. Both fail closed; say so.
- `trusted_associations:` with a null value silently takes the default (`GitHubTrackerSettings.kt:181`).
- No GitHub specific test of the mid run stop; an overlong KDoc line in `GitHubTracker.kt` around lines 24 to 25.
