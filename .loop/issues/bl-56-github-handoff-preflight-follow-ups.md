## Agent brief

**Category:** bug

**Summary:** A blank entry in `tracker.required_labels` is refused at startup and on reload, and the bl-46 reload behaviour is proven while an attempt runs.

**Current behavior:**
- A `tracker.required_labels` list with a blank entry beside real ones, for example `[ready-for-agent, ""]`, starts. No issue is ever eligible, since eligibility requires every listed label to be non blank and present, and nothing says why. A reload to such a list makes a running issue not eligible. The preflight trims and drops blank labels before judging, so it does not see the problem. This is not specific to GitHub: the eligibility code is the orchestrator's, so the `files` tracker has the same hole.
- No test reloads the workflow while an attempt runs on the github tracker, so the original bl-46 symptom (a reload that empties `required_labels` in the middle of an attempt, then a move refused at the drain) is covered only by reading the code.
- The reload test of bl-46 rewrites the workflow file in place, so a tick that reads the half written file can record an extra `config_reload_failed` and satisfy the wait early.
- The adapter profile's sentence on a refused move has its bl-46 clause between the condition and the quoted message.

**Desired behavior:**
- A workflow whose `tracker.required_labels` holds a blank or whitespace only entry is refused at startup with a message naming `tracker.required_labels` and saying that a blank label matches no issue. On reload it is rejected the same way and the last good workflow stays, recorded as `config_reload_failed` with `invalid_config`. This holds for every tracker kind.
- A list of only real labels, with surrounding whitespace, behaves as today.
- A test starts a github run in which an attempt is running, rewrites the workflow so that `required_labels` is empty, and shows: the reload is rejected, the running attempt's move to `review` still removes the required labels of the last good workflow, and `issue_moved` is recorded.
- Tests that rewrite the workflow of a running Loop write a temporary file and move it into place.
- The profile sentence reads in order: the condition, the message, then that preflight already refuses it at startup and on reload so the tracker's refusal is a second line of defence.

**Key interfaces:**
- The workflow preflight that already refuses github handoff problems (`gitHubHandoffProblem` and its callers at startup and reload), and the loader of `tracker.required_labels` in `WorkflowFile`.
- `isEligible` in the orchestrator and `RetryTarget.of`, unchanged, as the rule the preflight must match.
- The `config_reload_failed` event and its `invalid_config` error.

**Out of scope:**
- Any change to eligibility itself.
- Partial label moves (bl-47) and the reload ordering of the tracker's labels (bl-48).

**Triage notes:**
- Decision: refuse a blank label at load and on reload for every tracker, with a message that names the key. Dropping blanks silently in eligibility would hide a typo such as a trailing comma, and bl-46 already took the "refuse what can never work" line.
