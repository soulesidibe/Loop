## Parent

None. Backlog, not scheduled in a milestone. Found in the Loop run review of 2026-11-16, in its section on context occupancy.

## What

Loop records every runner output line as a `runner_output` event cut at 2,000 characters (`RUNNER_OUTPUT_MAX`, `Orchestrator.kt:4464`; `RunObserver.kt:16`). Claude Code prints each assistant message as one stream-json line with its `usage` object near the end, so on any line with a tool call or long text the usage is cut off. The store therefore cannot say how full an agent's context was on any request, the number the 20 to 25 percent rule is about.

For the review, peak context had to be measured from Claude Code's own transcripts (`~/.claude/projects/<encoded workspace path>/<runtime_session_id>.jsonl`, matched to attempts through the `phase` event's `runtime_session_id`): 140 sessions, median peak 137K, worst 355K, 21 over 25 percent of a 1M window. The measuring script and its data were kept out of the repository.

Directions for triage: parse the usage from the full line before the event is cut, and record it per request (or keep the running peak per attempt), which is what m3-08 (context usage) and m3-09 (peak occupancy in the ledger and status) need; check that m3-08's design reads the uncut line.
