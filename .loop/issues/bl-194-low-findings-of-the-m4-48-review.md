## What

Low findings of the m4-48 review. Triage decides which are worth fixing.

1. **Other callers get an isolated hold.** `tracker()` in `OpenProject.kt` (around line 106) and `deliveryFor` in `Host.kt` (around line 239) default to a fresh `GitHubClients()`. Callers today are `loop approve`, `loop resume` and `loop trace`, short separate processes where a shared in memory hold could not apply anyway.
2. **No multi thread test of `RateLimitHold`.** The stale clear test (`SharedRateLimitHoldTest.kt`, around line 231) uses coroutine interleaving; a later edit that drops `@Synchronized` would pass.
3. **Clients and holds are never evicted.** `GitHubClients.kt` (around lines 66 to 68). After a reload that rotates the token, the old client keeps the old token in memory until exit. It is never used for the new settings; `DeliveryExecutors.built` already kept old tokens the same way.
4. **After a token rotation, delivery and the tracker sit on different holds.** Delivery picks up the new token on reload; the tracker keeps its startup token until restart (as before m4-48), so the shared hold does not cover both in that window.
5. **Clients are keyed by the raw `apiUrl` string.** A trailing slash or a case variant builds a second client. Harmless, both share the origin's hold.
