## Agent brief

**Category:** bug

**Summary:** A denied command that names the holdout folder through `$LOOP_HOME` counts as a policy denial, and the docs say what timestamps reveal.

**Current behavior:**
A Bash denial counts as a policy denial when its command names a hidden folder by its literal path, by `~`, `$HOME` or `${HOME}`. A command that spells the folder as `$LOOP_HOME/holdout/...` or `${LOOP_HOME}/holdout/...` is not matched, so if Claude Code denies it the turn can end as `turn_input_required` and the attempt fails. The spec decisions doc says a holdout's duration does not leak, while the timestamps of its two events give it.

**Desired behavior:**
- `HiddenFolders` also matches a hidden folder spelled from the Loop home: for a folder under the Loop home, the forms `$LOOP_HOME<rest>` and `${LOOP_HOME}<rest>`, compared like the home forms. The Loop home is given to `HiddenFolders` by its caller, the same value the attempt env carries.
- No change for file tool denials.
- The holdout section of the spec decisions doc says the `duration_ms` field is not recorded, and that the two event timestamps still bound the duration, accepted.

**Key interfaces:**
- `HiddenFolders` constructor and its Bash matching.
- The place the Claude Code runner builds `HiddenFolders` from the generated settings.

**Out of scope:**
- Tracking the shell's working directory (`cd ~/.loop && cat holdout/x`).
- The boundary and case rules of the text match, and the shared splitter (bl-58).
- The preflight rule on `$LOOP_HOLDOUT`.

**Triage notes:**
- Whether Claude Code denies `cat $LOOP_HOME/holdout/x.sh` with the variable unexpanded is still unverified. Matching more is harmless, the class KDoc says so.
- Merging this issue into bl-58 was considered and not taken: bl-58 owns the shared splitter, this issue adds the spelling and the doc correction.
