## What

Triage decides which are worth fixing.

1. **Medium. The schema version does not mark namespaced ids.** Since m4-12 every new event, attempt, ledger, claim, wait and park row carries `default:<id>`, while `SCHEMA_VERSION` stays 7 (`SqliteEventStore.kt`, around line 709). The store already refuses a newer version (around lines 1048 to 1056), so a bump to 8 with no DDL would make a downgrade fail loudly. Today an older binary opens the store silently and reads `default:<id>` as a native id: its waits and claims are orphaned, ledger and trace by bare id miss the new rows. Suggested fix: bump to 8, and write the downgrade consequence in `docs/spec-decisions.md` "Namespaced issue ids" (it is written nowhere).
2. **Low. A bare id with a colon reads as namespaced.** `NamespacedId.parse` and `read` (`NamespacedId.kt`, around lines 35 and 47) read a pre m4-12 bare id like `abc:def` as tracker `abc`. GitHub and files ids never hit this.
3. **Low. `AttemptTool` opens the store with `AS_STORED`.** `AttemptTool.kt` (around line 96). Safe today since it reads by attempt id only; a future read by issue there would miss namespaced rows.
4. **Low. Two single row reads have no order.** `SELECT_PARKED_ONE` and `SELECT_WAITING_ONE` match `IN (?, ?)` with no ordering; both forms can coexist only after a downgrade.
5. **Low. Changing `tracker.id` orphans rows.** A `tracker.id` changed after namespaced rows exist reads `default:<id>` rows as a foreign tracker. Untested and undocumented.
6. **Low. Doc drift.** PLAN (around line 871) says the primary keeps bare ids, but new primary rows are `default:<id>`, and logs and events of a single tracker project show `default:<id>` until m4-47.
7. **Low. Machine wide reads mislabel other projects.** `toLedgerRow` for `SELECT_MACHINE_ATTEMPTS_SINCE` labels other projects' bare rows with the opening project's primary id. Cosmetic.

Area: `SqliteEventStore.kt`, `NamespacedId.kt`, `AttemptTool.kt`, `docs/spec-decisions.md`, `docs/PLAN.md`.
