## What

Under `preset: agy`, `AcpRunner.resumeSession` returns null because each session runs with a fresh isolated `--gemini-dir` that is deleted when the session stops, so the saved session is gone. A dead `agy` process or a network hold loses the session's work and context. Generic ACP already resumes with `session/load`.

Keep the isolated folder for the life of the attempt instead of the session, so a respawned `agy acp` with the same `--gemini-dir` can `session/load` the session id. Delete it when the attempt ends, and keep the stale folder sweep for dead runs. Triage decides whether the folder may outlive a session given the isolation goals of `.loop/specs/gemini-support.md`.

First check that `agy` 1.5.x advertises `loadSession` in its `initialize` answer and restores the session from the folder.

- [ ] The launch and capabilities sections of `docs/plugins/runner-acp.md` state the new folder lifetime.
- [ ] A real `agy` run confirms the loaded session keeps its history (judgment call, recorded in the issue).

## Agent Brief

**Category:** enhancement
**Summary:** under `preset: agy` the acp runner keeps the isolated `--gemini-dir` folder past its session so a dead `agy` process and a network hold resume the session with `session/load`.

**Current behavior:**
Each `agy acp` session runs with a fresh isolated `--gemini-dir` (`AgyIsolationDir`) that is deleted when the session stops. `AcpRunner.resumeSession` returns null under `preset: agy`, so a network hold starts a new empty session. A dead `agy` process fails the turn. `agy` 1.5.16 advertises `loadSession` in its `initialize` answer, and the Gemini spike proved `session/load` works across processes when the folder is kept.

**Desired behavior (decided in triage):**
1. **Folder lifetime:** the isolated folder holds the agy session store, so it is kept after the session stops. It is removed when the next attempt of the same issue resumes it and that session stops for good, when the issue reaches a terminal state, or by the stale sweep. The sweep keeps removing folders of dead runs; a kept folder records which issue and runtime session it belongs to, so the sweep and the resume can find it.
2. **Respawn:** a turn whose `agy` process is gone starts a new `agy acp` with the same `--gemini-dir` and calls `session/load` with the session id, `cwd` and `mcpServers`, then `session/set_model`, then runs the turn. At most once per turn.
3. **After a network hold:** `resumeSession(ctx, runtimeSessionId)` under `preset: agy` finds the kept folder of that runtime session and resumes it the same way. When no folder is found, it returns null and Loop opens a fresh session, as today.
4. **Isolation on resume:** before `session/load`, Loop rewrites `antigravity-cli/settings.json` with the strict settings and refuses to resume when the folder holds anything Loop did not expect at its root (fail closed, fresh session). The protected workspace roots check runs before the load and every turn, as today. `strict_mcp`, `--sandbox`, `--disable-telemetry` and the permission policy are unchanged.
5. **Failure:** a `session/load` error, or an `initialize` answer without `loadSession`, gives a fresh session, never a half resumed one, with a `loop:` line saying why.

**Key interfaces:**
- `AgyIsolationDir`: lifetime and lookup by runtime session id; the stale sweep.
- `AgentRunner.resumeSession(ctx, runtimeSessionId)` under `preset: agy`.
- The launch, stop and capabilities sections of the runner's profile doc, and the isolation section of `.loop/specs/gemini-support.md`.

**Acceptance criteria:**
- [ ] `./gradlew :plugins:runner-acp:test` passes, with fake ACP server tests for a respawn, a resume after a hold, a missing folder, a tampered `settings.json`, an agent without `loadSession`, and the folder removal at each of its three ends.
- [ ] `AgentRunnerContract` passes for the acp runner with `resumeSession` returning a session under `preset: agy`.
- [ ] `docs/plugins/runner-acp.md` and `docs/spec-decisions.md` state the new folder lifetime and the resume.
- [ ] One real `agy` 1.5.16 run confirms a loaded session keeps its history, written up in a comment (judgment call).

**Out of scope:**
- Generic ACP without a preset, which already resumes.
- Updating the pinned `agy` version.
- Changing when Loop calls `resumeSession` (the m4-46 soft limit rule).
