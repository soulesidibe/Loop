## What

Under `preset: agy`, `AcpRunner.resumeSession` returns null because each session runs with a fresh isolated `--gemini-dir` that is deleted when the session stops, so the saved session is gone. A dead `agy` process or a network hold loses the session's work and context. Generic ACP already resumes with `session/load`.

Keep the isolated folder for the life of the attempt instead of the session, so a respawned `agy acp` with the same `--gemini-dir` can `session/load` the session id. Delete it when the attempt ends, and keep the stale folder sweep for dead runs. Triage decides whether the folder may outlive a session given the isolation goals of `.loop/specs/gemini-support.md`.

First check that `agy` 1.5.x advertises `loadSession` in its `initialize` answer and restores the session from the folder.
