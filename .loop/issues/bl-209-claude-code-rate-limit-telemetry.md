## What

Claude Code writes `rate_limit_event` lines in its stream JSON, with `rate_limit_info` (status, `rateLimitType`, `resetsAt`, `unifiedWindows` utilization, overage status). The recorded streams in `plugins/runner-claude-code/src/test/resources/streams/` hold them, for example `real_two_turns_one_process.jsonl`. `StreamJsonMapper` drops them today (`StreamJsonMapperTest` asserts the line is removed), so `loop trace` shows no rate limit for Claude runs, while the Codex runner maps `account/rateLimits/updated` to `rate_limit` events (m3-21).

Map each `rate_limit_event` line to the same `rate_limit` runner event the Codex runner emits: limit id `claude`, each unified window with its used percent and reset time, and `reached` when the status is not `allowed`. Skip a line that changes nothing, as the Codex runner does.
