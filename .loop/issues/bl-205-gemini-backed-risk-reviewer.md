## What

Today `riskReviewerFor` in `cli/src/main/kotlin/loop/cli/Host.kt` always runs the merge risk assessment through `ClaudeCodeRiskReviewer`, whatever `runner.kind` did the work (`m4-06`). When running issues on `runner.kind: acp` (`preset: agy`) under `delivery.policy: auto` with `pull_request.merge`, Claude Code must still be installed for the reviewer.

Add a Gemini-backed `RiskReviewer` (using `agy` in read-only mode or `acp` with read-only permission gating and holdout denial) so workflows running on Claude Code or Codex can use a Gemini model as their independent merge risk reviewer, and workflows on machines without Claude Code can run auto-merge risk assessments with Gemini.

Area: `cli/src/main/kotlin/loop/cli/Host.kt`, `plugins/runner-acp/`, `plugin-api/src/main/kotlin/loop/api/RiskReviewer.kt`.

## Agent Brief

**Category:** enhancement
**Summary:** a Gemini merge risk reviewer, the `agy` twin of the Codex reviewer of bl-214, picked when `kinds.code.delivery.risk.reviewer` names a `gemini-` model.

**Current behavior:**
`RiskReviewerRuntime.of(model)` returns `Codex` for `gpt-`, `codex-` and `o<n>` models and `ClaudeCode` for everything else, so a `gemini-` reviewer model is sent to Claude Code, which refuses it. A machine with only `agy` cannot run `policy: auto` with merge.

**Desired behavior:**
1. **Selection:** `RiskReviewerRuntime` gains `Gemini` for models starting with `gemini-` (trimmed, any case). `riskReviewerFor` builds the Gemini reviewer for it, and the startup warning that names a missing reviewer command covers `agy` the way it covers `claude` and `codex`.
2. **The review:** one `agy acp` turn under `preset: agy` in the issue workspace, run by `AcpRunner` so the preflight, version pin, isolated `--gemini-dir`, `--sandbox`, strict MCP, protected roots check and env policy are the runner's. The model is the one of the request, set with `session/set_model`. Its command comes from `runners.acp.command` when the workflow's runner is acp with `preset: agy`, else `agy acp`.
3. **Read only:** the permission policy of a review declines every command (`execute`) and every write, edit, delete or move, and allows reads and searches except under the holdout folder. No Loop tool is passed (no `mcpServers`).
4. **The answer:** the text of the turn's final agent message, with the session's tokens and no cost. A turn past `RiskReviewRequest.timeoutMs` is stopped and is `RiskReviewError.Timeout`; a turn that fails, asks for input, cannot start or ends with no agent message is `RiskReviewError.Crashed`, as for the Codex reviewer.
5. **No kept folder:** a review never resumes and never keeps its isolated folder; it is removed when the review ends.

**Key interfaces:**
- `RiskReviewerRuntime` and `riskReviewerFor`.
- `RiskReviewer` and the `CodexRiskReviewer` it mirrors.
- `AcpPermissionPolicy`: a read only mode.

**Acceptance criteria:**
- [ ] `./gradlew :plugins:runner-acp:test` passes, with fake ACP server tests for an answer, a timeout, a failed turn, a declined command, a declined edit and a refused holdout read.
- [ ] `./gradlew :cli:test` passes, with tests that `gemini-4-neon-high` picks the Gemini reviewer, `sonnet` keeps Claude Code and `gpt-6.1-sol` keeps Codex.
- [ ] `docs/plugins/runner-acp.md` and the reviewer section of `docs/spec-decisions.md` describe it.

**Out of scope:**
- Changing the Claude Code or Codex reviewers.
- Warning when the reviewer and the worker use the same runtime.
- Non `gemini-` models that `agy` also serves.
