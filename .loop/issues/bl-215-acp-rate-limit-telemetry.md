## Agent Brief

**Category:** enhancement
**Summary:** when `agy` reports an exhausted Gemini quota, the acp runner gives the hold the quota's reset time as `retryAfter`, and records the limit as reached.

**Current behavior:**
`AcpErrors` maps a rate limit error (429, `rate_limit` codes, `RESOURCE_EXHAUSTED`) to `runner_unavailable`, and reads a retry time only from `retryAfterMs`, `retry_after_ms`, `retryAfterSeconds` or `retryAfter` keys of the error data. A Gemini quota error carries none of them, so the run level hold probes after 1 minute, then 2, 4 and so on up to 15 minutes, spending a probe attempt each time for hours until the quota resets.

**Desired behavior:**
1. **Reset time:** on a `runner_unavailable` rate limit error, the runner reads the wait from, in order: `quotaResetTimeStamp` (minus now), `quotaResetDelay`, a `RetryInfo` `retryDelay`, all searched in the error data at any depth (including a nested Google error body inside a string field), then the message text `Your quota will reset after <duration>`. Durations use Google's format (`4h23m27.7s`, `27s`, `850ms`). The first valid positive value becomes `TurnFailed.retryAfter`. A past timestamp or an unparsable value is ignored, never a failure. Nothing found keeps today's behavior.
2. **Hold:** no change to `RunnerHold`. It already takes `retryAfter` when longer than its backoff, on every period, so one probe runs at the reset time.
3. **Telemetry:** with a reset time found, the turn also emits the `rate_limit` runner event the Codex runner emits, limit id `gemini`, the model from the error (else `runners.acp.model`) as its name, `reached` true and the reset time, with no used percent. `loop trace` prints it. If the event cannot carry a window without a used percent, record the reset in the `turn_failed` reason instead and say so in a comment.
4. **Redaction:** no account id, email or token from the error reaches an event, a log line or a comment.

**Key interfaces:**
- `AcpErrors` retry time extraction and `RunnerEvent.TurnFailed.retryAfter`.
- The `rate_limit` runner event as the Codex runner emits it.
- The error mapping section of the runner's profile doc.

**Acceptance criteria:**
- [ ] `./gradlew :plugins:runner-acp:test` passes, with tests built from the logged 429 body: details in the error data, the body nested in a string, the message text only, a past timestamp, and no reset at all.
- [ ] A test shows a hold period equal to the parsed reset time, not the 1 minute backoff.
- [ ] `docs/plugins/runner-acp.md` states the reset time sources and the `rate_limit` event.
- [ ] The first real quota exhaustion under Loop confirms which form `agy acp` sends, written up in a comment (judgment call, after merge).

**Out of scope:**
- A usage percent before the quota runs out.
- Switching to another model when one model's quota is exhausted.
- Changes to `RunnerHold` or the hold rules.
