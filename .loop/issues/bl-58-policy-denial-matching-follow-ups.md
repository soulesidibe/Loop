## Agent brief

**Category:** bug

**Summary:** A denied command that names a deny listed command with sentence punctuation glued to it counts as a policy denial, and the two command tokenizers become one.

**Current behavior:**
`ClaudeSettingsFile.isDenied` splits a denied command into words on blanks, quotes, backslashes, shell operators and list punctuation, then looks for a deny listed command as a run of whole words. Punctuation such as `.`, `:`, `!`, `*`, `#` and `@` is not a break, so a heredoc or a commit message whose prose says `Never run git push.`, `use gh.`, `git push: denied`, `**gh** is denied`, `*git push*`, `git push!`, `git commit --amend.` or `#gh pr` is not a policy denial. If Claude Code denies such a command, the turn fails as `turn_input_required` and the queued move is dropped. `HiddenFolders` splits commands with its own, narrower pattern. The spec decisions doc says in one row that a prefix rule can be dodged with `sh -c "gh ..."` and in the next that a command which only quotes one is denied too, and it dropped "in error" where it describes `turn_input_required`.

**Desired behavior:**
- Before matching, each word loses leading and trailing sentence and markup punctuation: `.`, `:`, `!`, `?`, `*`, `#`, `@`, `~` and `_` at its edges. Punctuation inside a word stays. So every example above is a policy denial, with the last word of a deny listed command and with the first.
- A path stays one word: `/usr/bin/gh` and `./gh` are not policy denials through this rule (the existing launcher path rule for operator commands is unchanged), and neither are `file.gh`, `v1.2.push` or `git-push`.
- Everything that is a policy denial today stays one.
- One splitter serves both the deny list matcher and the hidden folder matcher, with the wider set of breaks. The hidden folder matcher's results for paths do not change, except where the wider breaks find a hidden path the narrow ones missed.
- The spec decisions doc reconciles the two rows in one sentence (a prefix rule alone can be dodged by quoting, and Loop classes a denial of a quoted or mentioned deny listed command as a policy denial whichever rule Claude Code applied), restores "in error" where the text describes when `turn_input_required` is returned if that is what the code does, and says that a bare `gh` word anywhere in a denied command counts, by design.

**Key interfaces:**
- `ClaudeSettingsFile.isDenied`, its `WORD_BREAK`, `deniedCommands` and the operator command rule.
- `HiddenFolders` and its own `WORD_BREAK`.
- `StreamJsonMapper`, the caller that classes each entry of `permission_denials`, unchanged in behaviour apart from the wider match.

**Out of scope:**
- Changing the deny list itself or the generated settings file.
- Detecting that the allowed half of a denied compound command never ran.
- Recording a real Claude Code denial as a fixture.

**Triage notes:**
- Decision: widen now, without recording a real denial first. Matching more only keeps a turn going after a denial the agent already saw, matching less fails the turn as `turn_input_required` and drops the queued move (the bl-33 bug). Trimming punctuation at the edges of a word, rather than splitting on it, keeps `v1.2`, `file.kt` and `/usr/bin/gh` from starting to match.
- A bare `gh` word matching anywhere is accepted as is, harmless by the same asymmetry, with one sentence in the docs.
- Wontfix: a denied compound command hides that its allowed half never ran. Checks run host side, and it is the same on main for a command starting with `git push`.
- bl-36 touches the same matcher family (`HiddenFolders`) and leaves the shared splitter to this issue.
