## Parent

None. Backlog, filed on 2026-11-16 from a review of how Loop enforces code quality.

## What happens

Coverage shows that code ran, not that a test would fail if it were wrong. An agent can write tests that cover the change and assert nothing useful. The `weaker_assertions` guard only compares assertions the diff changes.

## Proposal

An optional, slower check that runs mutation testing (for example Pitest) on the files the result changes only, and refutes when the mutation score of those files falls below a floor. The surviving mutants go into `loop.verify_findings`.

## Open questions

- Cost: scoping to changed files and a time limit, or running it only before the merge check.
- Whether it belongs in the verify contract or in the merge risk assessment as a fact that sets a floor.

## Acceptance criteria

- [ ] A result whose new tests let mutants of the changed code survive below the floor is refuted.
- [ ] The run is scoped to changed files and has a time limit.
