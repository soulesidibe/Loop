## Parent

None. Backlog, filed on 2026-11-16 from a review of how Loop enforces code quality.

## What happens

Loop parks a result as `unverified` when a kind has no checks, but a `code` kind whose only check is `true`, or a build with no tests or static analysis, verifies every result. Loop cannot tell a strong contract from a weak one, so its guarantee is only as good as each repository's config.

## Proposal

- Warn based on the check types a kind declares, not by guessing from shell strings: a `code` kind with no `changed_line_coverage` check, no `ratchet` check, or nothing but `diff_policy` and `acceptance_commands`, gets a warning at config load naming what is missing.
- A kind silences the warning with an explicit opt out that carries a reason.
- Optionally, record a contract strength summary in the evidence summary and as a fact for the merge risk assessment.
- Later: ship a default contract preset per ecosystem (Gradle, npm, Cargo) that a kind can extend.

## Acceptance criteria

- [ ] Loading a `code` kind with a weak contract prints a warning naming what is missing.
- [ ] A kind can silence the warning with an explicit opt out that carries a reason.
