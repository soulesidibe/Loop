## Parent

None. Backlog, filed on 2026-11-16 from a review of how Loop enforces code quality.

## What happens

The verify contract of the `code` kind in `WORKFLOW.md` runs `./gradlew --no-daemon build`, which compiles with warnings as errors, runs the tests and runs ktlint. ktlint checks formatting only. Nothing catches complexity, swallowed exceptions, unused code or risky constructs, so an agent can deliver a verified result that is correct but sloppy. `docs/PLAN.md` section 6.4 uses detekt in its own example, Loop does not.

## Proposal

- Add detekt to the `loop.kotlin-jvm` convention plugin, wired into `check` so `./gradlew build` runs it.
- Generate a baseline for the findings that exist today, so the change lands green, and protect the baseline file in `WORKFLOW.md` guards.
- Start from the default rule set, then tune it in a config file under `build-logic/` or `config/`.

## Notes

The build scripts, `gradle/` and `build-logic/src/` are protected paths, so an agent cannot make this change. It is likely `ready-for-human`.

## Acceptance criteria

- [ ] `./gradlew --no-daemon detekt` passes.
- [ ] `./gradlew --no-daemon build` passes and runs detekt.
- [ ] The baseline and detekt config are protected in `WORKFLOW.md`.
