## Parent

None. Backlog, not scheduled in a milestone.

## What

Found in the Fable 5.2 review of #50 (m2-12), reproduced with real git.

What is known:

- Workspaces are git worktrees of the main checkout, so they share refs with it. `git branch -f main HEAD` is refused in a worktree, but `git update-ref refs/heads/main HEAD` works and moves the operator's local `main`. The same goes for any other branch or tag, and for `.git/info/exclude` and the shared config.
- This predates m2-12. m2-12 makes it matter more because `diff_policy` resolves `guards.base` (default `main`) at check time (m2-13 has a comment on pinning the base).
- `docs/adr/` and the workspace docs should say whether workspaces are meant to be isolated from the operator's refs.
- Possible directions for triage: a clone per workspace instead of a worktree, a pre or post attempt check that the operator's refs did not move, or a read only ref namespace.

What is confirmed. A worktree shares with the operator's repository everything but HEAD, the index, `refs/bisect`, `refs/worktree` and `config.worktree`: all refs (branches, tags, `refs/stash`, `packed-refs`, `refs/loop/base/*`), `.git/config` (`core.hooksPath`, aliases), `info/exclude` and `info/attributes`, the hooks and the object folder. From a worktree, `git update-ref refs/heads/main <commit>` moved the main checkout's `main`, `git tag -d` deleted its tag and `git config core.hooksPath` landed in the shared config. Claude Code's deny rules match prefixes only (`git -C . update-ref` gets past them, `docs/spec-decisions.md` around line 1409) and the command runner has no sandbox.

Why a clone, not the alternatives. More deny rules are bypassable (`git -C`, aliases, scripts, writing under `.git`). A ref audit after each turn cannot tell the operator's or other attempts' ref writes from the agent's. A reference-transaction hook in the operator's repository was bypassed in the recheck with `-c core.hooksPath=/dev/null` and by writing the ref file. Per worktree config (`extensions.worktreeConfig`) does not stop a plain `git config` writing the shared file. A Loop owned bare mirror with worktrees protects the operator but not attempts from each other. A plain local clone hardlinks objects, which a future sandboxed agent could write through. `git clone --shared` borrows objects read only through alternates and owns its refs, config, hooks and info, and is the shape the M5 sandbox needs.

Performance, measured: the same as a worktree. On 40,000 files with Loop's real hook sequence, worktree 3.55 s, `clone --shared` 3.75 s; on 100,000 files 15 to 25 s either way. File writes dominate, history size does not count. Importing an agent commit back took about 0.2 s.

Threat model, to state in the ADR: mistakes and casual misuse by an agent, not a hostile agent. Verification still runs the agent's build code unsandboxed as the operator, and `git push /abs/path` or any write by absolute path stays possible until the M5 sandbox.

## Agent Brief

**Category:** bug
**Summary:** an opt in `workspace.git: clone` that makes each workspace a `git clone --shared` of the project, with its own refs, config, hooks and info, so nothing an agent runs in its workspace changes the operator's repository through git.

**Current behavior:** Loop's worktree hooks make each workspace a worktree of the project repository, sharing refs, config, hooks, info and objects. An agent can move the operator's `main`, other branches and tags (other attempts' `loop/<key>` included), `refs/loop/base/*`, and the shared config. Delivery and the merge check rely on the workspace writing its commits into the project's object store, and `refs/loop/base/<base>` is seen in the workspace only because refs are shared.

**Desired behavior:**
1. **The key.** A new optional `workspace.git: clone` in `WORKFLOW.md` front matter, parsed next to `workspace.root` in `WorkflowFile.kt`. Without it nothing changes and the hooks own the folder as today.
2. **Creating the clone.** With `clone`, when Loop creates a new workspace folder and before `after_create` runs, it runs `git clone --shared --no-checkout --no-tags <project repository>` (the folder of `WORKFLOW.md`), then:
   - removes the `origin` remote (in the recheck a plain `git push origin HEAD:refs/heads/other` from the clone moved the project's refs);
   - copies the project's repository local `user.name` and `user.email`, if set, into the clone's config;
   - writes a keep ref in the project, `refs/loop/workspace/<key>`, at the start commit, so a `gc --prune=now` in the project after a branch deletion cannot remove objects the clone borrows (the recheck broke a clone with `bad object HEAD` that way); Loop deletes it when it removes the workspace;
   - creates and checks out `loop/<workspace key>` (the name from `PullRequestDelivery.branch`), starting from the project's `refs/heads/loop/<key>` when it exists, else from `LOOP_BASE_REF`, else from the resolved base (the order of `resolveAttemptBaseRef`).
   It sets no sparse pattern: that stays the hook's job.
3. **Reuse.** A reused workspace (retry, restart) that already is a clone of the project keeps its branch and is never reset. A folder whose `.git` is neither absent nor a clone of the project fails the attempt with a named reason.
4. **Pinned host git.** Every git command Loop runs in a clone runs through `WorkspaceGit` with the existing `PROJECT_PINS` and minimal environment, since the clone's config is agent owned (a `core.fsmonitor` set in the clone ran on an unpinned `git status` in the recheck).
5. **Base and head are commit ids Loop resolved.** Whenever Loop writes `refs/loop/base/<base>` in the project (the base fetch before an attempt, a verification, the merge check), it also writes the same commit to `refs/loop/base/<base>` in the clone before the hooks and the agent run, so the prompt's `git merge refs/loop/base/<base>` works. Loop never reads a ref of the clone to choose a base, a diff base or a push target: `diff_policy` and delivery use the commit ids Loop resolved in the project, for every kind in clone mode (this also closes, in clone mode, the unpinned `guards.base` of kinds without pull request delivery, bl-32).
6. **Import before push.** Before any push of a workspace commit (the `PullRequestDelivery` push, the merge check push of the merged head), and on a verified verdict on a clean committed fingerprint, Loop imports that commit into the project host side: a fetch by the verified commit id with `transfer.fsckObjects`, through the isolated path `GitPush.kt` already uses, without the token, then writes `refs/heads/loop/<key>` in the project at that commit. The push then runs unchanged from `GitPush`'s temporary repository. `GitPush.verify` and `objects()` are checked against the imported branch and the project's object folder.
7. **Only Loop writes project refs.** In clone mode Loop writes no project ref other than `refs/heads/loop/<key>`, `refs/loop/base/*` and `refs/loop/workspace/<key>`.
8. **Removal.** `before_remove` and removal keep working; deleting the folder deletes the clone, the imported branch stays, the keep ref is deleted.
9. **Docs** (files agents may edit): a "Clone workspaces (extension, bl-28)" section in `docs/spec-decisions.md` and a clone section in `docs/workspaces.md`, covering usage, what stays shared (objects only, read only), what is lost compared with a worktree (the operator's git hooks such as husky or lint no longer run on agent commits, the project's `info/exclude` and `info/attributes`, LFS objects, submodules and git-crypt keys are not shared, `branch.loop/<key>.merge` is unset), the keep ref, and the threat model (mistakes and casual misuse, not a hostile agent; build code and absolute path writes stay possible until the M5 sandbox).
10. **Protected edits** go under `residual_human_steps`, each with its exact proposed text: Loop's `WORKFLOW.md` gets `workspace.git: clone`; `scripts/hooks/worktree-after-create.sh`, `worktree-before-run.sh` and `worktree-before-remove.sh` accept a workspace that is a clone of the project (set the `.loop/issues/` sparse pattern, check out `loop/<key>`, no `git worktree add` or `worktree remove`); an ADR in `docs/adr/` records the isolation and the threat model; the `docs/PLAN.md` section 19 row for bl-28 is updated.

**Key interfaces:** `spec-core/src/main/kotlin/loop/core/workspace/WorkspaceManager.kt` (`prepare`) and `Workspaces.kt`; `spec-core/src/main/kotlin/loop/core/workflow/WorkflowFile.kt` (the `workspace` block); `Orchestrator.kt` (`execute`, `attemptBase`, `resolveAttemptBaseRef`, removal); `spec-core/src/main/kotlin/loop/core/delivery/PullRequestDelivery.kt` and `MergeCheck.kt`; `plugins/tracker-github/src/main/kotlin/loop/tracker/github/GitPush.kt` (`objects`, `land`, `push`, `verify`) and `GitHubDelivery.kt`; `WorkspaceGit` (the pins); `spec-core/src/main/kotlin/loop/core/verify/Verification.kt` (the base fetch, the `diff_policy` base). Tests to extend: `cli/src/test/kotlin/loop/cli/WorktreeHooksTest.kt`, `PullRequestDeliveryCommandTest.kt` (the loopback git server), `TestRepo.kt`, `LoopFixture.kt`. Grep large files, never read them whole.

## Acceptance criteria

- [ ] A real git test with `workspace.git: clone` and a command runner agent that, from its workspace, runs `git update-ref refs/heads/main HEAD`, `git update-ref refs/heads/feature HEAD`, `git update-ref refs/tags/v1 HEAD`, `git -C . config core.hooksPath /tmp/x`, appends to `.git/info/exclude`, and tries `git push origin HEAD:refs/heads/other`: afterwards `git for-each-ref` in the project is byte for byte what it was before the attempt apart from `refs/heads/loop/<key>` (Loop wrote it at the verified commit) and the keep ref, the push fails because the clone has no `origin`, and the project's `.git/config` and `.git/info/exclude` are unchanged.
- [ ] The same agent script against a worktree workspace (today's hooks) shows the project's `main` moved, so the test proves the clone is what protects the refs.
- [ ] A new clone starts on `loop/<key>` at `LOOP_BASE_REF` when set and at the project's `refs/heads/loop/<key>` when that branch exists; a reused clone keeps its commits and is never reset; a folder with a foreign `.git` fails the attempt with a named reason; the project's `user.name` and `user.email` are copied when set.
- [ ] Keep ref: with a live clone, deleting its start branch in the project and running `git reflog expire --expire=now --all` then `git gc --prune=now` leaves the clone working (`git -C <clone> log -1` succeeds); removing the workspace deletes `refs/loop/workspace/<key>`.
- [ ] Pins: a `core.fsmonitor` (or `core.hooksPath`) set by the agent in the clone's config is never executed by any git command Loop runs in the clone, shown by a test whose hook writes a marker file.
- [ ] In a clone, `git merge-base --is-ancestor refs/loop/base/main HEAD` and `git merge refs/loop/base/main` work after Loop's base fetch, the ref is at the fetched commit, and moving that ref in the clone does not change the base `diff_policy` uses.
- [ ] End to end against the loopback git server: pull request delivery from a clone pushes the verified commit, imported by commit id with fsck, and a merge check that merges a moved base pushes the merged head; both commits are in the project's object store before the push.
- [ ] Without `workspace.git`, every existing workspace, delivery and merge check test passes unchanged.
- [ ] `docs/spec-decisions.md` and `docs/workspaces.md` describe clone workspaces, what is lost compared with a worktree, the keep ref and the threat model. The `WORKFLOW.md` switch, the three hook script changes, the ADR and the PLAN section 19 row are listed under `residual_human_steps` with their exact proposed text.
- [ ] `./gradlew build` passes.

## Out of scope

- An OS or container sandbox (M5, PLAN 11.2 layer 2); writes by absolute path and agent build code run by verification.
- A ref audit after each turn, a reference-transaction hook, more deny rules.
- Replay of a commit that was never imported, and making `clone` the default (part 2, a separate issue).
- Sparse checkout by issue area (reviewed on 2026-11-26 and not scheduled: it saves seconds against a build of minutes and conflicts with `diff_policy` and agent search).
- Filters and merge drivers named by `.gitattributes` (bl-55, M5).
- Editing `WORKFLOW.md`, `scripts/hooks/`, `docs/adr/`, `docs/PLAN.md` or `CONTEXT.md` (protected; human steps).
