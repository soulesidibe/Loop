## What

Found in the Fable 5.2 review of #50 (m2-12), reproduced with real git.

What is known:

- Workspaces are git worktrees of the main checkout, so they share refs with it. `git branch -f main HEAD` is refused in a worktree, but `git update-ref refs/heads/main HEAD` works and moves the operator's local `main`. The same goes for any other branch or tag, and for `.git/info/exclude` and the shared config.
- This predates m2-12. m2-12 makes it matter more because `diff_policy` resolves `guards.base` (default `main`) at check time (m2-13 has a comment on pinning the base).
- `docs/adr/` and the workspace docs should say whether workspaces are meant to be isolated from the operator's refs.
- Possible directions for triage: a clone per workspace instead of a worktree, a pre or post attempt check that the operator's refs did not move, or a read only ref namespace.
