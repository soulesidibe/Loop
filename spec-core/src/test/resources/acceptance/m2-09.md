## Parent

[Loop, M1 to M3](../specs/loop-m1-to-m3.md)

## What

Spec testing decisions: the acceptance criteria commands of each issue are run by Loop as visible checks in M2. Add a check type that reads the commands of the issue's acceptance criteria (a backticked command on a criterion line, the convention of `docs/agents/issue-tracker.md`) and runs each one; criteria without a command are listed as judgment calls in the evidence, never as passed. Area: verification module, issue parsing in the files tracker.

## Acceptance criteria

- [ ] A criterion line with one backticked command produces one check; a line without a command produces a judgment call entry (test on fixture issues).
- [ ] A kind can declare `{ type: acceptance_commands }` next to its other checks (test).
- [ ] Commands run in the workspace with the same timeout and rerun rule as `command` checks (test).
- [ ] The convention for writing a runnable criterion is stated in `docs/agents/issue-tracker.md`.
- [ ] `./gradlew --no-daemon build` passes.
